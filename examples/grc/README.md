# GNU Radio 120 MS/s duplex reference

Open vst_bridge_120_duplex.grc in GNU Radio Companion, regenerate and run. Close any previously opened copy of the graph first: an editor retains its loaded document even after the file changes on disk. vst_bridge_120_duplex.py is generated by grcc and also runs directly from the radioconda environment.

The graph repeats a precomputed +1 MHz tone, converts CF32 in the native Soapy plugin, and displays the actual full-rate RX Qt FFT/waterfall. Source and RX buffers are at least 1,048,576 items; TX source/sink work size is 262,144. The main-after-init snippet performs these scheduler settings, shows the Qt window before streaming, and contains optional in-application capture hooks. Preserve it during regeneration. GNU Radio thread priority is not implemented on this Windows build and is not used.

Center: 2500 MHz; TX peak: -10 dBm; RX reference: -20 dBm; both directions: 120 MS/s. RF is explicitly enabled in the Soapy sink for the adjacent-antenna reference test. For RF-off operation, replace both rf_enabled=true settings with false. Disable GQRX DSP before starting duplex: only one RX consumer may attach.

Stop the graph to turn RF off and show No client data in TX Monitor. Start the graph again to resume; the Bridge never automatically restarts RF. A genuine hardware/active-stream fault remains an Error.

The 2.2 validation launches the generated script's normal main() in a separate process, without a flowgraph wrapper or GR_CONF_DEFAULT_BUFFER_SIZE environment setting. The former 2.1 wrapper-only result and manual TIMEOUT evidence are retained. Latest measured acceptance and actual application images: ../../docs/VALIDATION.md.
